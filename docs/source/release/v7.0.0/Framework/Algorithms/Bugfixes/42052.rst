- Shape definitions now apply the ``rotate-all`` and goniometer rotations to every primitive. Cuboids given as four corner points, cones and infinite cones previously ignored them and were left unrotated. This affects samples whose shape was copied onto an oriented workspace with :ref:`algm-CopySample`, since the corner-point form is the one generated internally by, for example, :ref:`algm-FlatPlateAbsorption`.
- A rotated shape's bounding box, rendered mesh and volume now describe where the shape actually is. These come from a second reading of the shape definition that did not apply the rotations, so a rotated sphere, cylinder, hollow cylinder or cone was described in one place by the surfaces used to test whether a point is inside it and in another by everything sized or drawn from it. Cuboids and hexahedra were unaffected. This matters wherever a bounding box stands in for the shape, such as choosing the region to dice when integrating over a rotated sample.
- :ref:`algm-EstimateScatteringVolumeCentreOfMass` no longer rotates the sample shape twice when the shape already carries the goniometer rotation. :ref:`algm-CopySample` bakes the destination workspace's goniometer into the shape, while :ref:`algm-SetGoniometer` alone leaves the shape in its own frame; both leave the same goniometer on the run, so the rotation was previously applied again to an already-rotated shape. Shapes now report the rotation applied to them and only the remainder is used, so both routes give the same centre of mass. Results change for workspaces whose sample was copied onto an oriented workspace - in a scanned gauge volume test case the reported centre moved by over 3 mm.
